# C 轮：本机中英混合检索

## 使用方式

1. 先完整更新文档索引，再打开“更多 → 智能搜索”。
2. 下载模型，或选择已复制到本机的模型目录。
3. 点击“建立／继续语义索引”。窗口显示进度，可暂停，重新进入后继续；已有向量会复用。
4. 点击“启用混合搜索”，直接输入中文操作描述。仍可选择功能分类或手册范围，点击结果定位到英文原文。

全局设置增加“搜索”页，提供 **关键词／关键词＋语义／语义**、模型目录和推理线程数。初始仍为关键词模式，模型和语义索引都通过明确操作建立；启动、阅读和普通索引更新不自动下载或进行推理。

“混合”和“语义”模式的搜索文本在本机处理，不调用查询翻译 API。原有关键词模式继续沿用已有翻译设置，在线服务可能收到未覆盖的中文词语。阅读翻译设置独立于检索模型。

## 模型与安装

采用 Multilingual E5 Small 的固定 INT8 ONNX 转换，模型加分词文件约 135 MB。此轮优先形成 CPU 便携部署的实测基线；只提供一个经过验证的模型预设，后续可用同一接口比较更大模型和独立重排器。

原模型为 [intfloat/multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small)，使用 MIT 许可、384 维向量，按发布者要求为查询和文章分别加前缀，使用注意力掩码均值池化与 L2 归一化，最多 512 tokens。转换文件来自 [Xenova 的 ONNX 发布目录](https://huggingface.co/Xenova/multilingual-e5-small/tree/761b726dd34fb83930e26aab4e9ac3899aa1fa78/onnx)，CPU 会话使用 [ONNX Runtime](https://onnxruntime.ai/docs/api/python/api_summary.html)。

下载固定在修订 `761b726dd34fb83930e26aab4e9ac3899aa1fa78`；两个文件分别检查大小与 SHA-256，通过校验才替换正式文件。支持 HTTP Range 续传，服务器不支持续传时从头下载当前文件。暂停、断网或程序退出保留 `.part` 文件，已校验的完整文件不会重复下载；遇到校验失败可重试。下载锁与索引锁由操作系统释放，异常退出不会留下永久占用。

运行时仅读取本地 ONNX 和 tokenizer.json，不执行仓库 Python 代码，也不通过 Hugging Face SDK 自动获取文件。目录中的 model-info.json 记录来源、许可、修订、维度、处理方式和校验清单。模型身份使用这些内容的指纹，不使用本机绝对路径。

## 核心和数据契约

| 文件 | 职责 |
| --- | --- |
| core/embedding.py | 固定模型清单、校验下载、本地 CPU 推理、进程内会话复用 |
| core/semantic.py | 来源分段、增量向量索引、范围检索、文章聚合及融合排序 |
| core/tasks.py | 跨进程互斥，防止两个任务相互覆盖或清理结果 |
| core/search.py | 搜索模式协调、原查询语义召回、关键词回退及结果解释 |
| gui/semantic.py | 模型状态、下载、进度、暂停续建和启用入口 |

核心不依赖 Qt，关键词模式也不加载 ONNX Runtime 或 NumPy。推理、文件校验、SQLite 和扫描任务都在界面后台执行。线程数默认 2，可在设置中调整，模型推理请求使用锁协调。

现有文档库保持 SQLite schema 2；向量层为独立的可重建扩展，通过 semantic_schema_version=1 验证版本，未来未知版本明确拒绝。semantic_models 记录模型规格、维度、向量类型、分段版本、文档集合签名、状态与进度；semantic_passages 记录模型指纹、片段 ID、库内路径、原文哈希、片段文本、SourceLocation、向量和构建代次。

分段使用 B 轮的正文块和标题层级。同一章节内合并短文本，长文本重叠切分，保留片段对应的来源块。向量存储为归一化小端 float32，余弦相似度用于排序。每个来源仍使用原文内容哈希，不能把语义相关性当作正文事实或答案。

## 增量、暂停与迁移

按模型／分段版本和片段内容识别已完成向量，默认每批 8 个片段提交。暂停后保留已提交结果，当前批次返回后停止，不再提交下一批；计数阶段暂停也可重新开始。再次建立会复用已完成内容。

文档更新后，检索只使用与当前文档哈希一致的向量，已删除文章也会立即从候选中排除。状态显示需要更新；完整续建成功后清理旧片段。失败保留先前可用数据，允许重试，不清理阅读位置、译文或用户术语。纯索引重建导致行号变化不需要重新推理；未变化的片段仍可复用。

B 轮的快照与验证副本流程包含向量表。完整副本保持库 UUID、来源引用和模型指纹，复制模型目录并调整本机位置后即可复用。模型缺失、损坏、组件不可用或没有有效向量时，界面明确显示原因并返回可用的关键词结果。

## 排序、范围与界面

关键词与语义通道先分别按文章聚合，再进行 reciprocal-rank fusion；精确标题保留优先级，标题命中的术语数提供有限加权。避免直接混用 BM25 与余弦分数的不同尺度。

混合模式可用已识别术语补充召回，但未展开的词语会明确记录；语义通道始终使用完整原始问题。结果包含 channels、semantic_score、signals 和原有 reason/source 字段；悬浮可查看命中依据，底栏显示搜索模式及必要回退信息。余弦分数不是正确率，不作为百分比显示。

功能分类和模块范围在向量候选 SQL 中生效。检索分批读取至多 1024 个向量，仅保留有限数量的最佳文章候选，避免整库载入内存。当前使用精确向量扫描，耗时仍随范围内片段数增长；本轮没有 ANN、跨编码器重排、问答生成或图谱。大库延迟与领域准确率需要继续用真实语料评估，不能用小样本速度推断整库表现。

## 本机验证

- 106 项核心测试通过，包括暂停续建、向量复用、修订和删除过滤、失败恢复、模型版本隔离、副本迁移、锁互斥、下载续传和校验、配置迁移、过期查询取消及故障回退。
- C 轮 13 项 GUI 验收通过，使用真实 CPU 模型、构造手册和独立配置，检查进度、模式保存、中文检索、原文跳转、过期查询与缺失模型回退；原生 Windows 150% 缩放查看截图。
- B 轮 15 项 GUI 和整页翻译 14 项回归通过。
- 真实 B33 Part Design 的 12 篇文章构成受限候选集，共 76 个语义片段。5 个固定中文描述的目标排名分别为 1、2、1、1、1，关键词模式均无结果；检查了结果来源可重定位。首次构建约 4.2 秒，单次查询及来源核对约 0.06–0.10 秒；续建约 0.02 秒、无需重新推理。以上是小样本记录，不能代表整库检索质量或速度。

报告及截图为忽略提交的 data/stage-c-gui.json、stage-c-model.png、stage-c-search.png、stage-c-real.json。模型保存在忽略提交的 data/search-models/e5-small；未修改个人配置或手册原文。

## 便携构建

增加 search 开发依赖组，CI 安装相同 CPU 组件；Nuitka 配置包含 ONNX 原生 DLL，开发诊断检查 ONNX Runtime、tokenizers 和 NumPy。用户继续只通过便携 EXE 使用，不需要安装 Python。检索权重可在软件中下载或复制已有模型目录，发行包不自动包含本机索引或检索权重。

CI 仍只构建、打包和校验制品，不运行上述测试。本轮没有执行新的整包 Nuitka 编译或发布，编译制品和独立电脑验收仍须在发布时完成。
